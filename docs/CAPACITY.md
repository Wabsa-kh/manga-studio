# Daily production capacity

At the reference pace of approximately 207 spoken words/minute, one hour needs about **12,420 words** and two hours about **24,840 words**. Actual duration is measured after speech generation. A shorter last part is allowed. `daily_target_minutes` records the 60–120-minute throughput goal; `part_minutes` retains the selected 45–60-minute part boundaries. The target does not override quotas or manufacture missing content.

Current local planning allowances: Flash Lite reader 440 requests/day, Hydrogen writer 18/day, Gemini Flash TTS 9/day. These are not confirmed-current provider entitlements; project/model 429 responses override them. No keys are rotated to bypass limits. Reader requests also include subject geometry and phrase-focus planning, not only OCR.

Packing across units targets 2,200 spoken words per TTS request. A live 2,200-word Gemini TTS benchmark succeeded: **649.12 seconds of audio generated in 125.3 seconds**, with 18,905 reported total tokens. It used previously cached narration as test input, not a new production script. This demonstrates one larger request, not a multi-day sustained rate. Ideal arithmetic is roughly 6 calls for one hour and 12 for two hours, before boundary slack/retries. With a 9-call local allowance, two hours/day is not established. A video every day also depends on backlog, download availability, Google/Colab availability and completed quality checks.

The first Isekai pilot: 36 source pages, 1,250 spoken words, 362.33 seconds. Linear extrapolation would be about 358 source pages/hour, but chapter density varies; this is a planning estimate from one unit, not a demonstrated sustained rate. The whole downloaded collection has 1,897 pages. The earlier run stopped at 64 pages extracted and one 36-page unit rendered after repeated reader 503s. Software now applies a cooldown instead of a permanent stop for that known failure.

The revised 720p30 visual pilot rendered 362.33 seconds in about 271.5 seconds on the local CPU, including encoding/verification. Cloud CPU performance and GPU upscale speed have not been benchmarked. No GPU is required for the camera renderer; Colab GPU is for ESRGAN upscaling. Free Colab GPU sessions are not guaranteed.

GitHub-hosted jobs have a six-hour limit. The configured active work budget is four hours with a longer job timeout for saving. Waiting on tomorrow's API quota should end the worker, not consume an overnight runner. Private-repository Actions minutes and Drive storage have account-dependent included limits. A one-hour daily production job is not necessarily free to run for an entire month: check the account's Actions allocation and measured job minutes. See [GitHub's limits](https://docs.github.com/en/actions/reference/limits) and [billing documentation](https://docs.github.com/en/actions/concepts/billing-and-usage).
