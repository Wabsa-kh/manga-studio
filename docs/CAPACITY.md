# Daily production capacity

At the reference pace of approximately 207 spoken words/minute, one hour needs about **12,420 words** and two hours about **24,840 words**. Actual duration is measured after speech generation. A shorter last part is allowed. `daily_target_minutes` records the 60–120-minute throughput goal; `part_minutes` retains the selected 45–60-minute part boundaries. The target does not override quotas or manufacture missing content.

Current Google route safety ceilings are Flash-Lite reader 440 requests/day, Hydrogen writer 18/day and Gemini Flash TTS 9/day for each configured quota scope. The installed pool contains four Google, seven OpenRouter and one NIM credential. Key counts are not multiplied into a confirmed daily-hour entitlement. Google scopes use known project identity or the owner's separate-account declaration; observed shared project identities merge usage. OpenRouter keys share one provider budget. Reader requests include subject geometry and phrase-focus planning, not only OCR.

Packing across units targets 2,200 spoken words per TTS request. A live 2,200-word Gemini TTS benchmark succeeded: **649.12 seconds of audio generated in 125.3 seconds**, with 18,905 reported total tokens. It used previously cached narration as test input, not a new production script. This demonstrates one larger request, not a multi-day sustained rate. Ideal arithmetic is roughly 6 calls for one hour and 12 for two hours, before boundary slack/retries. Multiple account credentials improve routing options but do not establish a sustained two-hour daily entitlement. Output also depends on backlog, download availability, Google/Colab availability and completed quality checks.

The first Isekai pilot: 36 source pages, 1,250 spoken words, 362.33 seconds. Linear extrapolation would be about 358 source pages/hour, but chapter density varies; this is a planning estimate from one unit, not a demonstrated sustained rate. The whole downloaded collection has 1,897 pages. The earlier run stopped at 64 pages extracted and one 36-page unit rendered after repeated reader 503s. Software now applies a cooldown instead of a permanent stop for that known failure.

The revised 720p30 visual pilot rendered 362.33 seconds in about 271.5 seconds on the local CPU, including encoding/verification. Cloud CPU performance and GPU upscale speed have not been benchmarked. No GPU is required for the camera renderer; Colab GPU is for ESRGAN upscaling. Free Colab GPU sessions are not guaranteed.

The configured active work budget is four hours with a longer job timeout for saving. Brief pacing waits continue within a run; long quota resets end the worker until a later run. Standard public GitHub-hosted Linux runner time is free under [GitHub's billing rules](https://docs.github.com/en/actions/concepts/billing-and-usage). This does not grant additional Drive capacity, GPU availability or API quota. See also [GitHub's limits](https://docs.github.com/en/actions/reference/limits).
